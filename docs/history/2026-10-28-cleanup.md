# Git history cleanup — 2026-10-28

Checkpoint binaries are distributed only through
[Hugging Face](https://huggingface.co/ksusu/QHFlow2-QH9).
The GitHub release checkpoint archives were removed before this cleanup.
An audit of all published branches and tags found no model checkpoint binaries
in Git history. The large Git objects were bundled water sample data and caches.

## Removed data

The complete history of `dataset/water/` and `dataset/water_shard/` was removed:
raw SchNOrb water archives/databases, processed tensors, LMDB shards and their
cache metadata. The [removed-file inventory](2026-10-28-removed-data.json)
records the original paths, object hashes and sizes. The original water archive
remains downloadable as described in [dataset/README.md](../../dataset/README.md).

All 63 existing commits retain their parent relationships. Every remaining
file at every mapped commit was checked for identical path, mode and Git blob.
This includes all source, configuration, benchmark evidence, licenses and
`src/models/modules/Jd.pt` (a small mathematical constant, not learned weights).
The main branch has an additional documentation/ignore-rules commit.
A verified Git bundle preserves the complete original history offline.
Existing experiment worktrees and checkpoint files were left unchanged.

## Historical source identity

The rewrite changes commit IDs and the targets of the two existing release
tags, but preserves their source/configuration contents. This is a one-time
storage cleanup, not a model or benchmark revision. Version labels stay the same.
The GitHub releases keep their publication/draft status and assets.

## Existing clones

Use a fresh clone for new work after this cleanup. Keep any old checkout with
local edits or active experiments until that work is safely migrated. Do not
merge or push the old history back: it would reintroduce the removed data.
Fetch into a new directory rather than resetting an active experiment checkout.

GitHub-managed closed-pull-request refs and cached commit views may still refer
to old history; they are not fetched by a normal clone. This cleanup concerns
the branch/tag history distributed to new clones, not erasure of those caches.
